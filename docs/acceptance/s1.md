# S1 live acceptance — M7 and M8

Operator script for the two attended acceptance steps of S1 (“brief me, then help me handle one
request”): **M7** (issue #26, live substrate) and **M8** (issue #27, restart and handling journey).
Plan source: `docs/plans/master_plan.md`, Phase 2 / S1, “Step M7” and “Step M8”.

**Status: M7 PENDING, M8 PENDING.** Nothing in this file has been run live yet. S1 is not accepted
until both steps are recorded below with real (not fake-mode) evidence. M7 runs before M8.
M5 (#13, two-day observation) and M6 (#14, publish check) remain separately open; this script does
not close them.

All commands are for **Windows PowerShell**. Run each block on its own and read its output before
the next; there is no `&&` in PowerShell 5.1.

## What is already proven, and what only M7/M8 can prove

| Proven by automated fake-mode gates (Steps 9–12) | Only M7/M8 can prove |
|---|---|
| Real app, routes, assistant service and SQLite store: briefing → prepare → edit → handled → close → restart → identical packet (`npm run smoke:assistant`, Vitest, Playwright) | The real Desktop shortcut and launcher start the journey on this machine |
| Revision conflicts between tabs, lost saves, unsaved-change guards, 390 px layout (Playwright) | The real Google Sheet is read correctly for a briefing (service account, real rows) |
| Composer envelope/schema parsing and failure codes, using a deterministic **fake** composer | The real authenticated `claude -p` CLI produces a useful draft and checklist for a real task |
| Planted synthetic secret-like text never reaches server logs or error bodies | Your real message text does not leak into the visible launcher window |
| “Handled” never writes to the (fake) Sheet; no send-capable code exists (grep test) | Nothing is sent or marked read in your real Gmail / WhatsApp, and the real Sheet row is unchanged |
| Corrupt/newer database fails closed; interrupted runs need explicit Retry | Whether the draft and checklist actually help you handle a real request |

Fake mode never calls the real Claude CLI, Google, Gmail or WhatsApp. A fake-mode pass is **not**
M7/M8 evidence.

## Ground rules (both steps)

- Use the real checkout and the Desktop shortcut you already use. Do not change `private/` files,
  settings, tokens or the Sheet's sharing for this test.
- **Do not alter global credentials.** Do not run `claude logout`, `claude login` / `/login`, or
  re-consent Google during the test. If the CLI or Google is not authenticated, stop and record
  M7 as **blocked (auth)**; re-authenticating can break another running session's login, so do
  that later, deliberately, not as part of this test.
- Pick a **benign** task (for example a reply to a family member or a school notice). Avoid
  anything sensitive, financial or security-related.
- Never paste message text, sender names, email addresses, phone numbers, sheet ids or file paths
  into the evidence section. Record only the fields it asks for.
- A **no-data** condition (no open tasks in the Sheet, no eligible task, a failed Sheet read) is
  recorded as such. It is not a pass.

## M7 — Live substrate smoke (issue #26)

### M7.1 Start from the Desktop shortcut

Double-click the **Yarvis** Desktop shortcut.

| Expected | If not |
|---|---|
| The browser opens `http://127.0.0.1:5173/` and lands on **Briefing** (`/briefing`) | Open the minimized “Yarvis” window on the taskbar; record the visible error class (port in use, install missing). Do not paste message text. |
| The minimized “Yarvis” window shows `[api] GET ...` lines with paths and status codes only | If you see message text in that window, record **privacy defect** (no content in the note) |

### M7.2 Refresh if needed

Open **Todos**. If the newest stored tasks are old, press **Refresh** and wait for it to finish
(it reads Gmail/WhatsApp read-only and updates the Sheet). Then go back to **Briefing**.

| Expected | If not |
|---|---|
| Refresh ends `done` (or `partial` with a named stage) | Record the stage and error code shown; a failed refresh does not block M7 if the Sheet already holds open tasks |

### M7.3 Build a briefing

Press **Build briefing**.

| Expected | If not |
|---|---|
| Within a few seconds a snapshot appears: “Saved just now”, an open count, up to 25 items, “Stored tasks from the sheet…”, sources with “freshness unknown” | “The last briefing failed”: record the error code shown; that is a **no-data / source failure**, not a pass |
| Items with a pending extraction say “Not ready to prepare” | — |
| “No open tasks in the sheet.” | Record **no data**; M7 cannot pass until a real eligible task exists |

### M7.4 Prepare one benign task with the real CLI

On one benign, eligible card press **Prepare reply**. Note the time.

| Expected | If not |
|---|---|
| A preparing state, then (normally well under 60 s) the Preparation page opens at `/preparations/<id>` | “Preparation failed” with a code on the card: record the code (`compose_timeout`, `compose_invalid`, `compose_failed`, `run_timeout`). If the code suggests auth, stop: **blocked (auth)** |
| The page says “Draft only: nothing is sent.”, shows the source excerpt, a draft, 1–12 checklist items and any questions; the meta line names your real model (not `fake-composer`) | If the model shows `fake-composer`, the server is in fake mode: stop and record **invalid run** |
| The draft does not invent dates, promises or names that are not in the source; unknowns appear as questions | Record **content defect** (describe the kind, not the text) |

### M7.5 Save an edit and reopen

Change one sentence of the draft and tick one checklist box, then press **Save**.

| Expected | If not |
|---|---|
| Status changes from “Unsaved changes” to “All changes saved”; the revision goes from 1 to 2 | Record the error shown; your text must still be in the editor |

Go to **Saved preparations**, open the same preparation again (or reload the page).

| Expected | If not |
|---|---|
| The edited draft and the ticked box are there, revision 2 | Record **persistence defect** |

### M7.6 Nothing was sent or marked read

| Check | Expected |
|---|---|
| Gmail (web or phone): the source email | Its read/unread state is what it was before M7.4; no new message in Sent |
| WhatsApp (phone): the source chat | No message sent by you; Yarvis sends no read receipts (unread state unchanged by Yarvis) |
| The Google Sheet, Todos tab, the prepared task's row | `status` still `open`; `updated_at` unchanged by Prepare/Save (Refresh in M7.2 may have changed it before) |
| `claude` in another terminal or session you had open | Still logged in and working (nothing was re-authenticated) |

M7 passes only if M7.1–M7.6 all match with a real task and the real CLI. Record the result below.

## M8 — Restart and handling journey (issue #27)

Run after M7 passes, on the same preparation (or another benign one).

### M8.1 Edit the draft and the checklist

Open the preparation from **Saved preparations**. Edit the draft, edit one checklist item's text,
tick a different box, add one question, press **Save**.

| Expected | If not |
|---|---|
| “All changes saved”; revision increases by 1 | Record the error; local text must be kept |
| Navigating away with unsaved edits asks first (Stay / Leave) | Record **guard defect** |

### M8.2 Close and reopen through the launcher

Close the minimized “Yarvis” window (this stops the server). Wait until
`http://127.0.0.1:5173/` no longer loads, then double-click the **Yarvis** Desktop shortcut again.

| Expected | If not |
|---|---|
| Yarvis starts again and opens on **Briefing**, showing the saved snapshot with its age | Record the startup error class |
| **Saved preparations** lists the preparation with the same revision; opening it shows every edit from M8.1 | Record **persistence defect** |
| No run restarted on its own; if one was running when you closed, it shows as interrupted with a Retry | Record **recovery defect** if anything re-ran automatically |

### M8.3 Mark handled; Todo completion stays separate

On the preparation press **Save and mark handled**.

| Expected | If not |
|---|---|
| State shows “Handled”; the note says nothing is sent and the Todo is not changed | — |
| **Todos** still lists the task as open; the Sheet row is unchanged | Record **store-ownership defect** |
| Completing the Todo is your separate, explicit action on the Todos page (optional; it is not part of “handled”) | — |

### M8.4 Inspect a stale briefing

Without building a new briefing, look at the Briefing page after some time has passed (or after a
Refresh that added tasks).

| Expected | If not |
|---|---|
| The snapshot shows its age (“Saved N min/h ago”) and still lists only what it captured | Record if it silently changed or claimed to be current |
| New tasks appear only after **Build briefing**; they are marked “New to this briefing” | — |

### M8.5 Controlled source-failure simulation (isolated, synthetic)

This runs a **separate, synthetic** Yarvis on other ports (8799/5185) with a throw-away private
folder. It never touches your real `private/` folder, settings, tokens, Sheet or running app. Do
**not** press Refresh or Prepare in this instance. Open a new PowerShell window in the repo folder.

1. Create the throw-away folders and settings:

Run in: a NEW PowerShell window @ your yarvis checkout (repo root); keep this window for steps 2–4, `$m8` lives in it · Model: n/a (operator step)

```powershell
$m8 = Join-Path $env:TEMP ("yarvis-m8-" + [guid]::NewGuid().ToString("N"))
New-Item -ItemType Directory -Force "$m8\data", "$m8\empty" | Out-Null
npx cross-env "YARVIS_PRIVATE_DIR=$m8\data" npm run setup
npx cross-env "YARVIS_PRIVATE_DIR=$m8\empty" npm run setup
[System.IO.File]::WriteAllText("$m8\empty-seed.json", '{"Todos":[],"Quarantine":[]}')
```

2. **Empty inbox** — a fake-mode instance whose synthetic sheet has no tasks:

Run in: the same M8.5 window @ your yarvis checkout (runs until Ctrl+C) · Model: n/a (operator step)

```powershell
npx cross-env PORT=8799 YARVIS_WEB_PORT=5185 "YARVIS_PRIVATE_DIR=$m8\empty" "YARVIS_FAKE_SHEET_SEED=$m8\empty-seed.json" npm run dev:fake
```

Open `http://127.0.0.1:5185/briefing`, press **Build briefing**, then stop the instance with
Ctrl+C in that window.

| Expected | Meaning |
|---|---|
| The run succeeds and says “No open tasks in the sheet.” with 0 open | Empty inbox: the source was read and had nothing |

3. **Missing data** — first a good synthetic snapshot, then the same folder with the Sheet
   unavailable:

Run in: the same M8.5 window @ your yarvis checkout (runs until Ctrl+C) · Model: n/a (operator step)

```powershell
npx cross-env PORT=8799 YARVIS_WEB_PORT=5185 "YARVIS_PRIVATE_DIR=$m8\data" npm run dev:fake
```

Open `http://127.0.0.1:5185/briefing`, press **Build briefing** (synthetic tasks appear), then
Ctrl+C. Now start the same throw-away folder in real mode. Its settings still hold the placeholder
sheet id and it has no service account, so every Sheet read fails as “not configured” before any
network call:

Run in: the same M8.5 window @ your yarvis checkout, after Ctrl+C stopped the fake instance (runs until Ctrl+C) · Model: n/a (operator step)

```powershell
npx cross-env PORT=8799 YARVIS_WEB_PORT=5185 "YARVIS_PRIVATE_DIR=$m8\data" npm run dev
```

Open `http://127.0.0.1:5185/briefing` and press **Build briefing**.

| Expected | Meaning |
|---|---|
| “The last briefing failed” with a source error, and the earlier synthetic snapshot stays visible labelled “Historical snapshot” | Missing data: the source could not be read; nothing is presented as current and no empty briefing is published |

4. Stop it (Ctrl+C) and remove the throw-away folder:

Run in: the same M8.5 window (it holds `$m8`) · Model: n/a (operator step)

```powershell
Remove-Item -Recurse -Force $m8
```
