Yarvis v0: a read-only to-do radar for WhatsApp and Gmail

One Refresh button pulls your allowlisted WhatsApp chats and your Gmail inbox since October 1, screens every message with Jev, turns the real asks into one-line to-dos, and lands them in a Google Sheet you can see on a small React page. Nothing is ever written back to WhatsApp or Gmail.

Done means all five of these hold on your real accounts (M4)

  • G1 A combined to-do list, each item tagged whatsapp or gmail.
  • G2 A Refresh button that pulls new messages and updates the list.
  • G3 The same entries visible in the Google Sheet (Todos and Quarantine tabs).
  • G4 A spam folder: the Quarantine page with Jev's scores and reasons.
  • G5 A pirate-mode toggle that swaps the UI strings and survives restart.
Guardrails, as enforced. Gmail: the OAuth scope is exactly read-only, tested by equality and re-checked against the token at every start. WhatsApp: the connector exports nothing that can send, and a test fails the build if a send or read-receipt call appears anywhere in the server. Sheets is the only module with a write scope. Quarantined mail never reaches Claude, and a Jev outage stops the run rather than letting unscreened mail through. Plan sections 1.1 and 1.2 carry the full mapping.
Why this shape

Three findings drove the design.

  • WhatsApp cannot be exported from code. Export Chat is a phone-side share action and the desktop app has no export. The only automatable read is a linked device, which is what Baileys is. Running it on demand keeps it a tool, not a daemon.
  • Gmail and Sheets are already solved in this workspace. pta_finance carries a scope-pinned read-only Gmail module and a row-targeted atomic Sheets client. Yarvis ports both patterns to TypeScript rather than inventing new ones.
  • Jev classifies, it never generates. That makes it safe to show it a hostile email. The generating model (Claude) only ever sees messages Jev cleared, and sees them wrapped as untrusted data with no tools.
POST /api/refresh whatsapp on-demand Baileys drain of allowlisted chats -> cache gmail OAuth(readonly) list+get since 2026-10-01 -> cache jev 1 call/message: phishing, malicious, spam, action quarantined = max(security) >= 0.50 actionable = !quarantined && action >= 0.60 extract claude -p --bare --tools "" (JSON array of 1..3 tasks) sheets upsert Quarantine rows, upsert Todo rows, save cursors

Agent defaults

Defaults worth your eyes. Reference by ID to tweak.

D1 Jev thresholds 0.50 / 0.60

What Quarantine when any of phishing, malicious, spam is at or above 0.50. Extract when action is at or above 0.60.

Why Jev's noul is a calibrated probability; 0.5 is the neutral line for a security filter, and a slightly higher bar on action keeps chatter out of the list.

Tweak Either number; both live in settings and the UI shows the scores.

D2 One Jev call per message

What All four questions ride in one request; the code throws away the action answer for quarantined messages.

Why Jev evaluates questions in isolation and never generates text, so batching halves calls without weakening the guardrail, which is "quarantined content never reaches Claude".

Tweak Two sequential calls if you want the action question literally never asked of flagged mail.

D3 Jev down means Refresh fails closed

What If Jev errors, the job stops at the jev stage with no sheet writes; messages stay cached for next time.

Why No unscreened message should ever be extracted or shown as a to-do.

Tweak Fail-open for WhatsApp only (it has no inbox-style spam exposure).

D4 Claude seam: bare, no tools, fast model

What claude -p --bare --tools "" --model claude-haiku-5-5 --output-format json, prompt on stdin, 60 s timeout, tree kill. Non-JSON or failure writes the row with the original text and a pending flag; next Refresh retries.

Why Your global config runs claude -p as a full agentic harness unless told otherwise (a workspace lesson). Pending beats dropping the to-do.

Tweak Model alias, timeout, or 1 action per message instead of up to 3.

D5 WhatsApp also gets the quarantine questions

What Allowlisted WhatsApp messages run the same four questions, so a phishing link in a group chat lands in Quarantine too.

Why The questions are free once the call is made, and the folder is more useful if it is complete.

Tweak Action question only for WhatsApp.

D6 Sheets via service account

What A service-account key writes the sheet; you share the sheet with its email once.

Why Keeps the Gmail OAuth token at exactly one scope. Same split pta_finance uses.

Tweak Reuse the Gmail OAuth client with a second token file for Sheets instead.

D7 Sheet schema and id formats

What Todos: id, source, status, action, original_text, sender, context, message_date, link, jev_action, created_at, updated_at. Quarantine: id, source, sender, context, message_date, link, three jev scores, reason, created_at. Ids: gmail:<msgId>, wa:<jid>:<keyId>, todo <msg>#n.

Why Enough to render, audit, and tune thresholds from the sheet alone.

Tweak Add or drop columns; headers are one shared constant.

D8 Sheet is the record, cache is a cursor

What JSONL caches under private/cache remember what was seen and scored; deleting them costs API calls, not data.

Why Re-runs stay idempotent and cheap, and you can hand-edit the sheet freely.

Tweak SQLite instead of JSONL if the cache grows past a few MB.

D9 Baileys drain window 8 s quiet, 60 s max

What The session closes after 8 s with no new events or 60 s total; presence off, full-history sync off, browser identity "Yarvis".

Why Short sessions keep the footprint of an unofficial client minimal.

Tweak Longer windows, or keep the session open while the app runs if M5 shows no backfill.

D10 Express on 127.0.0.1:8787, Vite on 5173

What Localhost-only binding is the entire auth model; Vite pinned with strictPort and host 127.0.0.1.

Why Single user on one machine; the Windows Vite rules from the workspace.

Tweak Ports, or Fastify/Hono instead of Express.

D11 Fake mode is a first-class run mode

What YARVIS_FAKE=1 swaps all five seams for seeded fakes; runtime reviewers, CI smoke, and your first click-through all use it.

Why Every build step can gate without credentials, and the UI can be seen before any account is linked.

Tweak None expected.

D12 Quarantine is its own page

What Four nav items: Todos, Quarantine, Connected apps, Settings.

Why A folder deserves a route, and three menus plus one folder stays simple.

Tweak Fold Quarantine under Settings as you first described.

D13 Refresh is an in-process job

What POST returns 202, the page polls status every 2 s, a second POST while running gets 409. No scheduler.

Why A refresh can take a minute with live Jev and Claude calls; the button should not hang.

Tweak Synchronous call if you prefer fewer moving parts.

D14 Body caps: 4000 chars stored, 2000 to Jev

What Plain text preferred over HTML; links extracted separately and included in the Jev state.

Why Keeps token cost and sheet cells small while giving Jev the parts that signal phishing.

Tweak Either cap.

D15 Reviewer flags

What Full reviewers (code plus runtime in fake mode) on Steps 1, 2, 6; code reviewers elsewhere; worktree isolation.

Why Those three steps change visible UI; the rest are connectors and seams the suite covers.

Tweak Downgrade to code everywhere for speed.

Not in v0

Cut on purpose.

  • Scheduled or background refresh. Manual button and CLI only.
  • Any write to WhatsApp or Gmail: sending, replying, labeling, archiving, read receipts.
  • Pirate voice in the data, a chat UI, voice input, calendar, reminders, notifications.
  • Hosting, multi-user auth, mobile layout polish beyond "works at phone width".
  • Attachments: only text bodies and link URLs are read.
